# Research Radar 首页 Hero 设计探索

## 1. 设计目标
- 新用户 5 秒内找到“上传论文并创建监控”入口。
- 空状态只有一个同级主 CTA。

## 2. 方案 A（推荐）：卡片式 Hero
- **排版布局**：
  - 左侧：标题“让公开文献替你盯住研究风险”，副标题一句话说明“上传论文 → 提取 Claim → 创建监控 → 持续输出影响/证据/行动”。
  - 右侧：一个可视化 Radar 插图占位。
  - 下方：一个包裹“上传论文并创建监控”主按钮的文件上传区。
- **空状态约束**：不再出现第二个同级按钮。

## 3. 方案 B：精简对话式 Hero
- **排版布局**：直接一个大输入框“上传论文或粘贴标题”，按钮“创建监控”。
- **辅助说明**：下方用三行说明“自动提取 Claim / 持续扫描公开文献 / 输出证据与行动”，减少装饰性文字。

## 4. 可用性评估

| 评估维度 | 方案 A | 方案 B |
| :--- | :---: | :---: |
| 5 秒发现 CTA | 4 | 5 |
| 空状态主按钮数量 | 5 | 5 |
| 信息架构复杂度 | 3 | 4 |
| 移动端宽度适配 | 3 | 5 |
| 开发成本 | 3 | 4 |

*(注：分数 1-5，5 分为最优)*

**推荐与风险评估**：
方案 A 视觉传达更丰富，能更好地展示产品的核心价值（Radar 概念）；风险在于实现成本相对略高，移动端需要特殊适配。方案 B 更聚焦操作，但表现力较弱。

## 5. 结论
先按方案 A 做探索性实现，不以视觉完成度作为发布验收门槛；后续可用性测试后决定是否保留。
