# Research Radar 发布回归清单

## 1. 登录/注册
- **检查命令/操作路径**：
  1. 打开应用，使用全新账号完成注册流程。
  2. 观察是否自动登录。
  3. 刷新页面或重启应用，检查是否记住登录态。
  4. 退出当前账号，再次使用相同账号登录。
  5. 检查历史创建的文档是否可见且归属正确。
- **通过标准**：注册后无需手动登录即自动进入系统；重启应用后无需重新登录；重新登录后历史文档不丢失、不属于其他用户。
- **记录方式**：屏幕截图或测试报告中勾选“通过/失败”。

## 2. 历史文档
- **检查命令/操作路径**：
  1. 登录已有测试账号（包含至少3份历史文档）。
  2. 验证历史文档列表是否完整展示。
  3. 随机打开其中2份文档，检查内容是否正确加载。
  4. 切换至另一测试账号，确认无法看到前一账号的历史文档。
- **通过标准**：历史文档列表可见且可正常打开；严格做到数据隔离，绝对不串账号。
- **记录方式**：测试报告日志及账号隔离验证结果。

## 3. 扫描速度
- **检查命令/操作路径**：
  1. 准备标准测试集（如包含10篇固定文献的项目）。
  2. 触发全局扫描操作，使用性能监控工具记录整体耗时。
  3. 多次运行取 p95 值（95% 请求的响应时间）。
- **通过标准**：以当前版本 p95 耗时为基线（当前基线值：__需填写具体数值__ 秒），新版本测试得出的 p95 耗时回退不超过 10%。
- **记录方式**：性能测试工具生成的报告链接，包含基线值与当次测试值对比，失败判定为耗时增加 > 10%。

## 4. 扫描状态
- **检查命令/操作路径**：
  1. 触发不同结果的扫描任务（正常耗时扫描、无结果扫描、网络断开等导致的失败扫描）。
  2. 观察界面 UI 的状态变化及提示信息。
- **通过标准**：
  - 用户能清晰区分“正在扫描”、“扫描完成但没有影响（无增量信息）”、“扫描失败”三种状态。
  - 扫描完成、失败或部分完成时，系统有统一的 Toast 提示或明确的页面状态指示器。
- **记录方式**：记录各种状态下的 UI 表现截图，确认符合设计规范。
