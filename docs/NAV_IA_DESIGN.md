# Research Radar 导航信息架构与可用性探索

## 现状风险
当前系统顶部导航包含的功能入口过多，导致在窄屏设备或较小窗口下出现横向滚动，部分关键功能入口被截断，影响用户体验与操作效率。

## 方案探索

### 方案 A（推荐）
- **设计思路**：将高频主流程进行归类，低频功能折叠。
- **具体分组**：
  - **主流程直接外露**：“论文 Claim” / “文献雷达” / “证据” / “行动”。
  - **折叠菜单**：将其余入口（周报、引文核验、深度调研、诚信雷达、课题组矩阵、运维、设置）收拢进入“更多”下拉菜单中。

### 方案 B
- **设计思路**：保留全部入口，但通过建立两层导航结构进行分流。
- **具体分组**：
  - **一级主流程**：项目内的核心主流程操作。
  - **工具 Tab**：项目级别的独立工具或全局功能。
  - **移动端适配**：在移动端或极窄屏环境下，使用抽屉式导航（Drawer）收纳所有入口。

## 可用性评估表

以下针对两个方案在五项关键指标上的评估打分（1-5分，5分为最优）：

| 评估维度 | 方案 A（推荐） | 方案 B（双层导航） |
| :--- | :---: | :---: |
| **主流程可达性** | 5 | 4 |
| **窄屏可见性** | 5 | 3 |
| **键盘焦点管理** | 4 | 3 |
| **入口可发现性** | 3 | 5 |
| **实现成本** | 5 (成本低) | 3 (成本高) |

## 结论
- **建议**：先验证方案 A（推荐方案）。
- **后续步骤**：通过进行可用性测试来决定是否最终落地实施。
- **注意**：本方案探索阶段的结论仅作设计参考，不直接作为开发版本的验收条件。
